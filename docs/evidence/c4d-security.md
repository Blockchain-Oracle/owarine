# C4d: the security review's findings, fixed (evidence)

Date: 2026-09-30 · lane C4d (`slice/C4d-security`, from main `ecdbf72`) · decisions K-210 to K-213

**Threat model.** The app runs publicly against a shared Canton participant, where one ledger user can act as all of our parties. The app's own code decides which party a visitor acts as. A visitor leases a seat (a party) with an ed25519 key, and parties are recycled to new visitors. So everything a visitor can read or act on must be bound to their **current lease**, meaning offsets at or after the lease's start, and never to the party alone.

**Out of this lane:** H1 and L5 `setRunner` (lane C8i, agents); M1 room token, L1 link brute force and L2 recycle race (lane C4c).

**Why K-210 and up.** Lanes C4c and C8i both claim K-204 in their branches (C8i also uses K-205 to K-207), so this lane starts at K-210.

## Trade-offs and what is left

- **H2, legacy rows.** A live desk row written before C4d keeps the old address. The web and the runner's reconcile accept it for the party's current lessee. The operator looks a trade's mandate up by the new address, though, so such a row cannot trade until discovery re-registers it under the new address. Discovery runs every 10 minutes and only for the current lessee. No deployment has live desks yet, so this is theoretical.
- **In-memory single-use caches.** The web's write-proof nonces (K-211), the handoff codes (K-212) and ops' HMAC nonces (K-213) live in process memory. That is correct for one web container and one ops container (AD-4). A second replica of either would need a shared store first.
- **M2a residual.** An app that starts its own handoff holds its own verifier, so PKCE alone does not stop it. What stops it is the person's tap on "Continue in the app as @handle", plus iOS's own "… wants to use … to sign in" prompt.
- **Not changed here: other lanes' files that also echo error text.**
  - `web/src/app/api/seat/link/route.ts:24` and `web/src/app/api/seat/link/join/route.ts:41` ("seat store unreachable: <db text>") belong to C4c.
  - `web/src/lib/agents.server.ts:42` ("registry unreadable: <text>") is touched by C4c.
  - Each is a one-line swap to `serverFault` (`web/src/lib/seat.server.ts`) once those lanes merge.
  - `web/src/app/api/push/drain/route.ts:30` (behind `PUSH_DRAIN_SECRET`) and `web/src/app/api/private/*` (not deployed on Canton) also echo text. The review did not list them.
