Owarine runs at <AppLink href="/markets">owarine.xyz</AppLink> on **Canton DevNet**. Its test funds have no cash value. The browser requests a firm quote, your seat accepts it, and Daml records the position. Oracle parties sign boundary prices. The resolver records the result and the settler pays it.

## System context

The browser and native app share the venue's server routes. The phone app exists in source; public distribution and physical-device acceptance are separate, unverified claims.

## The shared participant boundary

The venue, resolver, oracle and seat parties use one shared participant. Its configured ledger user can act as those parties. The browser's signing key authenticates a request to Owarine; the server submits the Daml command for the party attached to that lease.

The server must enforce that mapping. Seat routes derive the party from the current lease and scope history to the lease's start offset. The `no-party-from-request` invariant checks that routes do not take a party supplied by the caller. This is an operator and server trust boundary alongside Daml's contract rules.

A `Leg` has two stakeholders: its owner and the venue. Other seat parties cannot query it. The venue is the counterparty and can see it. See [Who sees what](/architecture/privacy).
